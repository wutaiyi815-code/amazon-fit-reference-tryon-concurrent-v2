# 亚马逊视觉需求表与版型库匹配

## 本地 Excel

只读以下两个工作表：

- `AIGC需求`：先用完整 SKU 精确命中记录，读取该行的 `SPU` 与 `版型`。
- `SPU数据`：再用上一步取得的 SPU，匹配 `SPU(业务通用)`、`主SPU(amz)` 或明确的 `SPU` 字段，读取 `二级类目-AM` 与 `三级目录-AM`。

SKU 字段可使用 `SKU`、`SKU号`、`产品SKU`、`图片SKU` 等明确包含 SKU 身份的表头。不得通过截断 SKU 文件夹名来猜 SPU，也不得用行号推断。匹配时只忽略大小写、首尾空格及 Excel 将纯数字显示为 `.0` 的差异；不得用包含关系把一个 SKU 匹配到另一个 SKU。

若同一数据表出现多个相同 SKU：

- 完全相同的非空值可去重使用，同时记录重复数量。
- 非空值冲突时停止该 SKU 的自动库匹配，交由主代理核对，不能静默取第一条。

## 钉钉规范化 JSON

通过 MCP 完整读取两个数据表后，写为：

```json
{
  "source": "dingtalk",
  "spu_data": [
    {
      "spu": "AE26XXXX",
      "category2": "Hoodie",
      "category3": "卫衣"
    }
  ],
  "aigc_requirements": [
    {
      "sku": "AE26XXXX-01TBLK-M",
      "spu": "AE26XXXX",
      "fit": "上装OVRZ02"
    }
  ]
}
```

保留重复记录。辅助脚本会按与 Excel 相同的冲突规则合并。

## 本地版型参考优先级

对每个逻辑产品单独判断：

1. 上装产品先看 SKU 的 `版型参考_上装`。
2. 下装或裙装先看 SKU 的 `版型参考_下装`。
3. 对应文件夹非空时，主代理必须查看全部候选图，选与实际产品类别、长度、松量、肩型/裤腿和整体廓形最接近的一张；不再查询版型库替换它。
4. 对应文件夹缺失或为空时，才允许查表格版型和版型库。
5. 表格版型为空、表格 SKU 缺失、目录无精确匹配或视觉候选不可靠时，`fit_reference` 保持 null。

## 版型库目录匹配

调用方必须通过 `--library "<版型库目录>"` 显式提供版型库根目录。辅助脚本不假设任何机器专属默认路径；目录不存在或不是文件夹时立即停止，并在日志中显示实际收到的路径。

第一层是品类目录，第二层是版型目录。一个目录名可以承载多个标识，常用 `_` 分隔；实际目录还可能出现全角斜杠 `／`。匹配时：

- 将 `_`、`／` 和 `/` 视为标识分隔符，忽略空标识。
- 忽略大小写和首尾空格。
- 优先用更具体的 `三级目录-AM` 完整匹配某个标识；无匹配时再用 `二级类目-AM`。
- 在匹配的品类目录下，用表格 `版型` 完整匹配第二层目录的任一标识。
- 不使用任意子串匹配。例如 `slim01` 不得匹配 `slim01-1`。
- 多个目录精确命中时保留全部候选，由主代理根据实际产品图和目录内容判断，不按目录枚举顺序拍板。

示例：

- `卫裤_Pants_Sweatpants_Jeans` 可匹配 `卫裤`、`Pants`、`Sweatpants` 或 `Jeans`。
- `oversized02_上装OVRZ02_上装OVRZ03` 可匹配其中任一完整版型标识。
- `slim01_` 的尾部空标识忽略，只匹配 `slim01`。

## 视觉选择标准

版型目录只负责缩小候选范围，最终仍要肉眼比较：

- 先确认同类：上装对上装、裤装对裤装、裙装对裙装。
- 再比较衣长/裤长、肩线、胸身容量、袖型、腰臀松量、裤腿形态、廓形及垂坠。
- 产品的颜色、面料、Logo、图案和装饰不是选择版型参考的主要依据。
- 无法可靠判断时不使用参考图，不能为了建立一一对应关系而强行选择。
